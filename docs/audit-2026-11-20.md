## Second pass (reviewer follow-up)

The first commit deferred several items. Closed now:

- **Critical: desktop app page-world tool access.** `contextIsolation` is `true`
  in the AI `BrowserView`. The `chrome` shim is a lexical binding inside the
  preload's isolated world and is never attached to `window`. Content scripts
  are concatenated and `eval`'d in that same isolated world, so they keep DOM
  access and tool IPC while page JavaScript can see neither `chrome` nor
  `ipcRenderer`. Main-world helpers (ChatGPT/Qwen network shims) stay in the
  page world via `webFrame.executeJavaScript` — they hold no privileged API.
  New `snapgent-app/test-main-world-isolation.js` proves the boundary with a
  stubbed preload run; mutations (AI-view `contextIsolation: false`,
  `window.chrome =`, `Object.defineProperty(window, "chrome", ...)`) all fail it.
  A follow-up review found no Critical/Required issues; its five test and
  edge-case nits (narrower static guard, array-valued storage, shared-scope
  proof, stale comment) were fixed.
- Roblox/EffectCraft targets are disabled by default in the standalone app's
  storage, since it ships only the `vscode` MCP server.
- Context task directories older than `ZS_CONTEXT_TTL_SECONDS` (24 h default)
  are removed on each `prepare()` call.
- `snapgent-app` has a `test` script so the new boundary check runs in CI.

## Deliberately not changed

- `bridge.py:813` — extension Origin is accepted without a token. This is documented pairing UX in `docs/security-and-ops.md`; a local process can forge Origin, so the allowlist is not a boundary against local processes. Changing it would break pairing. Residual risk stays.
- `bridge.py:1090` — `_change_server` has no lock. Its read-modify-write section has no `await`, so asyncio cannot interleave it; the theoretical thread race does not apply to this single-threaded event loop. Adding a lock would be dead code.
- `snapgent-app/package.json` — Windows dist references `bin/vscode_mcp.exe`, a gitignored build artifact produced before packaging. Removing it would break the packaged app; the Windows target matches the app's `.exe` server. Added a `test` script instead.
- Test-gap findings that need new stub-DOM infrastructure (innerHTML rendering fuzz, A2A failure-path suite) were not added. The world-boundary regression now has `snapgent-app/test-main-world-isolation.js`.
- E2E sandbox checks now fail closed on hosts without bubblewrap or netns. CI installs bubblewrap, so CI stays green. No skip path was added: recording a skipped security assertion as a pass was the defect being fixed. A local host that cannot sandbox cannot pass the live e2e by design.

## Risk the user must know

- The desktop app's AI view now isolates the IPC shim from page JS. The residual risk is structural: the agent reads tool commands out of the site's DOM, so a fully compromised provider page can still forge an assistant turn and induce a tool call. That is inherent to DOM-driven web AI, not to the IPC boundary. Continue to use only trusted provider hosts.
- The Origin-based bridge auth is intentionally weak against local processes. Keep `ZS_BRIDGE_AUTH=strict` where a local-process boundary matters.
